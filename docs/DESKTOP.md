# 桌面端与浏览器插件：要不要做、怎么做

结论先写在这里：**桌面端先不做原生 app，做「只读网页版」；浏览器插件优先做，用 WebDAV 直写。**

## 一、桌面端有必要吗

### 真实需求在哪

| 场景 | 手机能不能凑合 | 桌面的增益 |
|---|---|---|
| 几个月后想起一句话，翻回原文 | 能，而且更快 | 无 |
| 一次导入几百条书签、看导入报告 | 能，但屏幕小 | 大屏批量核对更省事 |
| 长文精读、做笔记 | 能 | 大屏 + 键盘翻页更舒服 |
| 保存正在看的网页 | 靠分享 / 剪贴板 | 插件一键，桌面端反而不是必需 |

所以「桌面 app」的价值集中在**阅读与批量整理**，不在保存。而保存这件事，浏览器插件比桌面客户端更贴近。

### 技术代价

现有代码是 Expo/React Native，关键依赖都绑在移动端：

- `expo-sqlite` → 桌面要换 better-sqlite3
- `@react-native-ml-kit/text-recognition`（端侧 OCR）→ 桌面要换 Tesseract / 系统 OCR
- `expo-share-intent`、`expo-media-library`、PackageInstaller → 桌面无对应物

三种做法与代价：

| 方案 | 复用程度 | 工作量 | 风险 |
|---|---|---|---|
| Tauri + 现有 React 代码（去掉 RN 层） | 中（解析器、查询、同步都能复用） | 3–4 周 | UI 要从 RN 重写成 Web |
| Electron 包一层网页版 | 低（等于新写一个只读客户端） | 1–2 周 | 包体 100MB+，和「轻」的产品气质冲突 |
| **只读网页版（WebDAV 客户端）** | 高（复用解析产物：Markdown 正文 + 元数据） | **3–5 天** | 无安装、无签名、跨平台 |

### 建议

先做只读网页版：打开 `trovia.html`，填 WebDAV 地址和账号，它把 `docs/*.json` 全拉下来，用 Markdown 渲染 + 本地索引（FlexSearch）搜索。电脑上「翻收藏」这件事就解决了，而且它同时是插件的落点。

等真正有人抱怨「网页版不能保存/不能整理」，再谈 Tauri。

## 二、浏览器插件怎么做

### 方案 A（推荐）：插件直写 WebDAV

插件不依赖任何服务器，也不依赖手机在线：

```
点击插件 → 读取当前标签页的 url + title
        → 组装一条 SyncRecord（与手机端同一份格式）
        → PUT <webdav>/trovia/docs/<id>.json
        → 手机下次同步拉到这条，自己抓正文、OCR、写摘要
```

要点：

1. **格式必须共用**：`{ id, updated_at, deleted_at, rev, payload }`，`payload` 里字段名与 `apps/mobile/src/local/sync-store.ts` 完全对齐。建议把 `@trovia/shared` 里的 `normalizeUrl`、`newId` 直接编译进插件，避免判重规则漂移。
2. **只投递「待抓」记录**：`parse_status: 'pending'`，正文交给手机端抓。理由是手机端已有整套解析 + OCR，插件里再实现一套必然分叉。
3. **凭据**：`chrome.storage.local` 存 WebDAV 地址与应用密码；坚果云要求应用密码，不是登录密码。
4. **权限**：`activeTab`、`storage`、`scripting`，加上目标 WebDAV 域的 `host_permissions`；不要申请 `<all_urls>`，那会吓到人。
5. **入口**：工具栏 popup（保存当前页）、右键菜单（保存链接/选中文字）、快捷键 `Alt+S`。
6. **失败处理**：本地排队重试（`chrome.alarms`，最多重试 3 次），popup 里显示「N 条待同步」。

MV3 的 service worker 不能常驻，所以不要设计「后台监听」这类逻辑，保存动作必须由用户触发。

### 方案 B：局域网直连

插件发现同一 Wi-Fi 下的手机/桌面端，走 HTTP 推送。优点是能立刻触发抓取，缺点是要处理 mDNS、配对、防火墙、iOS 后台限制，收益不大。**不建议。**

### 方案 C：什么都不写

复制链接，回到手机时首页的剪贴板提示已经能一键保存。零成本，但要用户回到手机。

### 工作量

- 骨架 + popup + 直写 WebDAV：**2 天**
- 右键菜单、快捷键、失败重试、多账号：**+1 天**
- 商店上架（Chrome Edge 可共用、Firefox 需微调 manifest）：**+0.5 天**

## 三、如果两个都做，顺序

1. 浏览器插件（2 天）：解决「电脑上看到的链接，手机上不用再找」
2. 只读网页版（3–5 天）：解决「电脑上翻收藏」
3. 桌面原生客户端：等前两个被用起来再说

第 2 步可以顺带把 `apps/web` 里那套自托管后端重新定位成「可选的服务端」，不是必需品。
