# Trovia 浏览器插件

把当前页存进 Trovia，稍后在手机里用一句话找回。

插件**不抓正文**：它只往你的 WebDAV 里写一条待整理的记录（链接、标题、站点），
正文、图片和索引交给手机端——手机上本来就有那套解析器，插件里再养一份只会让两边漂移。

## 装

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），右上角打开「开发者模式」
2. 点「加载已解压的扩展程序」，选这个目录 `apps/extension`
3. 工具栏上出现朱红书签图标

也可以 `npm run pack` 生成 `dist/trovia-extension.zip`，解压后再按上面加载。

## 配

点图标 →「设置」，填和手机端**同一处** WebDAV：

| 字段 | 说明 |
| --- | --- |
| 地址 | 云盘的 WebDAV 根地址，不带末尾 `/`，例如 `https://dav.jianguoyun.com/dav` |
| 账号 | 云盘账号 |
| 密码 | **应用密码**，不是登录密码；坚果云在「账户信息 → 安全选项 → 添加应用」里生成 |
| 目录 | 默认 `trovia`，要和手机端同步设置里的一致 |

保存时浏览器会弹一次「读取和更改您在 xxx 上的数据」——这是插件访问该域名所必需的主机权限，
只对这一个域名生效。

点「测试连接」先确认能连上，再去保存。

## 用

- 点图标 →「保存」
- 快捷键 `Alt+S` 直接存当前页（可在 `chrome://extensions/shortcuts` 改）
- 右键菜单：页面、链接、选中文字三种入口

存完手机下次同步就能看到，状态是「待整理」，手机端接着抓正文。

**用快捷键和右键保存时，工具栏图标会给反馈**：存成功打勾 ✓（绿色），失败打叹号 !（红色），
平时如果队列里还有待发送的记录，图标上直接显示条数。以前这两条路径是"静默"的——点了没反应，
也不知道到底存没存上。

**同一个页面再存一次不会变成两条**：记录 id 由链接算出，再存就是更新标题和时间覆盖原来那条。
弹窗会告诉你「这个页面 X 月 X 日已经存过了，再存会更新」。

没连上云盘时不会弹错就完事：记录进本地队列，每 5 分钟用 alarms 重试一次，弹窗底部显示
「N 条待发送」。service worker 被回收也不影响，队列在 `chrome.storage.local` 里。

## 边界

- 只处理 `http(s)`：`chrome://`、扩展页、本地文件不能存
- 正文不抓：登录墙、动态渲染这些手机端才处理得了
- 不在任何商店上架，只能按上面的方式加载

## 开发

```bash
npm test -w @trovia/extension   # 记录格式 + WebDAV 端到端（起一个最小 DAV 服务）
npm run pack -w @trovia/extension  # 打出可加载的 zip
```

CI 里有一个 `Extension` workflow：改到 `apps/extension/**` 就跑测试并打包，产物挂在 Actions 上。
之前这个包没有任何 CI，队列逻辑出错只能等用户发现。

`manifest.json` 的版本号跟随 App 版本（现在是 0.15.9），报问题时能直接对上。

记录格式必须和手机端逐字段一致：插件算出的规范化链接和 `doc_id` 一旦和手机端不同，
同一个链接会在云端变成两条。`test/sync.test.mjs` 的期望值来自手机端实现，改任何一边都要同步改它。
