一个框，两种用法

保存和找回本来就是一回事：你想留住某个东西，和你想找回某个东西。所以不需要两个入口。

粘的是链接 直接保存。抓正文、存下正文里的图片、写摘要与关键词，再建立本地索引。
写的是描述 当成一次检索。用你记得的任意细节——主题、某句话、作者、来源——去匹配已经存下的内容。
已经存了一堆 浏览器导出的书签、CSV、链接清单都能一次搬进来；重复的自动跳过，先给你看清楚会新增多少条再动手。
想换个地方 整库导出成 JSON 和 Markdown，正文、图片路径、时间都在里面，不留在任何服务器上。

怎么用

  1. 保存 粘贴文章、视频或网站链接即可。不用填标题，不用分类，不用打标签。
  2. 整理 在手机上解析正文、读图里的文字、生成摘要与关键词、建立本地索引。页面上能看到处理状态，失败的条目会说明原因。
  3. 找回 用一句自然语言描述你记得的大概内容，得到原文，以及「为什么找到它」。

图片里的字也读得出来

很多内容根本不在正文里：公众号的长截图、技术文章里的架构图和思维导图、小红书的图片笔记。Trovia 会把正文里的图片下载下来，用端侧 OCR 把上面的中文读出来，接在原文后面一起索引——所以那些字也能被搜到。

识别在你自己的手机上完成：图片不经过任何服务器，读出来的文字只写进本机数据库。

能读哪些页面

端侧抓取能力有限，这里如实说明。表格里的结论都可以用 scripts/probe-extract.mts 复现。

正常解析 微信公众号、掘金、少数派、CSDN、V2EX、GitHub、维基百科、简书，以及大多数个人博客和文档站。
只能拿到链接 知乎、Medium、豆瓣、36 氪这类有登录墙或人机验证的站点，端侧抓不到正文；Trovia 会明确告诉你「需要验证或登录」，而不是假装保存成功。
图片内容 正文里的图片会全部尝试 OCR，识别不出的图片跳过，不影响正文。

我们的四条承诺

这个产品很小，所以不想把话说满。只有四件事，写在这里当承诺看。

  1. 数据始终在你自己手里 收藏、正文、图片、索引都保存在这台设备上；要同步，就写进你自己的云盘。任何时候都能完整导出，随时带走。
  2. 不设功能墙 解析、读图里的字、按时间与意思找回——这些能力永远免费。付费只会出现在一件事上：你不想自己准备模型时，由我们代付。
  3. 先把中文站点读好 微信公众号、掘金、少数派、CSDN 这类页面优先修。读不到的时候会明确写清原因和你能做什么，不会假装保存成功。
  4. 存下来是为了找回来 这里没有「待读清单」，也不催你读。目标只有一个：几个月后你只记得一句话，也能翻回原文。

它不是什么

  • 不是书签管理器：不需要你维护文件夹和标签；旧书签一次性导入就行。
  • 不是知识库：不要求先整理、导入或建库。
  • 不是笔记工具：不提供编辑器，正文按原样保存。
  • 不是通用搜索引擎：只搜你保存过的内容，不混入互联网结果。

为什么找得回来

搜索时按标题、关键词、摘要、正文、图片文字、来源分别命中，再按权重融合排序：

标题匹配 只记得标题里的词
关键词 整理内容时提取的关键词，记得大概主题也能命中
摘要匹配 记得的是当时那段总结或文章开头
正文匹配 正文里出现过的词，中文按相邻两个字切分，不依赖分词器
图片文字 截图、图表、思维导图上的字，端侧 OCR 读出来后一起参与匹配
来源信息 记得作者、公众号或域名

每条结果都会给出匹配原因与命中片段，全部来自真实命中的内容，不会编造文章里没有的东西。 搜索在手机本地完成，不上传查询，也不调用任何模型。

边界与隐私

  • 所有收藏保存在你的手机本地，默认不上传任何服务器。
  • 图片文字识别在设备上完成，图片本身不会被上传。
  • 解析失败也保留原始链接，可随时打开原文或重新解析。
  • 不绕过登录、付费墙或任何访问限制，不执行网页里的脚本与指令。
  • 删除收藏会同时删除本地的正文与索引，之后搜索不会再出现。
